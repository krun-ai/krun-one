# Krun One v1 (text)

An **encoder-only decision model**: given a context and a typed question it returns a calibrated decision in one
forward pass — no text generation.

| question type | output |
|---|---|
| `choice` | one option among 2 … 128+ (intents, tools, routes, labels), or none (abstention) |
| `noul` | true / false for a proposition about the context |
| `score` | an ordinal level |
| `multi` | every option that applies |

* **Architecture:** K1-W1536-L22 — ModernBERT / mmBERT encoder (22 layers, hidden 1536, 24 heads, GLU FFN 2304,
  global attention every 3 layers, local window 128) + 2-layer decision head with option-marker scoring, a `[NULL]`
  slot and an answerability head. **879,356,931 parameters.**
* **Tokenizer:** mmBERT / Gemma-2 vocabulary (256k). Sequence: 1,024 tokens (option head budget 896, ≤ 48 tokens per
  option, long candidate lists are chunked).
* **Languages:** trained on English, Portuguese (BR / PT), Spanish (ES / LatAm) and French, incl. cross-language
  (context in one language, options in another).
* **Calibration:** per-family temperatures and a top-1 − top-2 margin abstention signal (thresholds fitted on a held-out
  split, 80% coverage serving point).

Code, training and every report: https://github.com/krun-ai/krun-one

## Usage

The checkpoint is the frozen artifact folder `krun-one-v1-text-final/` (checksums in `SHA256SUMS`, verified on load).

```bash
git clone https://github.com/krun-ai/krun-one && cd krun-one && uv sync
hf download krun-ai/krun-one-v1 --local-dir models
```

```python
from krun_one.v1.runtime import TextArtifact

a = TextArtifact.load("models/krun-one-v1-text-final", device="cuda", dtype="bf16")
a.decide({"context": "quero cancelar minha assinatura",
          "questions": {"q": {"type": "choice", "task_type": "intent",
                              "options": [{"id": "cancel_subscription"}, {"id": "check_balance"}]}}})
```

Tools are passed as options with descriptions (`{"id": "get_weather", "description": "…"}`); `task_type` selects the
calibration family (`intent`, `tool`).

## Results

KrunBench v1 validation (V eval) and external checks, bf16, RTX 4090:

| | |
|---|---|
| choice accuracy | 97.6% (intent 97.5%, tools 98.1%) |
| PT-BR / cross-language | 97.9% / 98.2% |
| k = 64 / k = 128 candidates | 95.8% / 90.6% |
| OOD AUROC · false acceptance at 80% coverage | 0.971 · 4.5% |
| Score (5 levels) MAE · Spearman | 0.60 · 0.84 |
| noul AUROC · multi micro-F1 · ECE | 0.973 · 0.917 · 0.015 |
| ToolACE v0 holdout | 90.1% |
| JevBench public items (231, external, evaluation only) | 53.2% (hard tier 30.6%) |
| latency (typical request / k = 128) | ~14–17 ms / ~44 ms p50 |
| memory | ~1.7 GB VRAM with bf16 weights |

## Limitations

* One encoder pass compares stated consequences well but **does not compute multi-step consequences** from a raw state
  (numbers against limits, chains of lookups, schedules); see the v1.1 research reports in the repository.
* Inputs longer than 1,024 tokens are truncated.
* True / false judgments that need reasoning are close to chance on external benchmarks.
* The abstention threshold is tuned for the text families; use the margin as an advisory signal elsewhere.
